Isoform is configured once, at startup, with [`configure()`](/reference/configure/). Optional native modules are listed in `isoform.config.json`, a file read both by `configure()` at runtime and by the native builds.

## `configure()`

```ts title="isoform.config.ts"
import { configure } from '@michelgutner/isoform';
import isoform from './isoform.config.json';
import { tokens } from './tokens';

configure({
  provider: 'auto',
  theme: tokens,
  breakpoints: { sm: 480, md: 768, lg: 1024, xl: 1280 },
  native: { remBase: 16 },
  modules: isoform.modules,
});
```

| Option | Type | Default | What it does |
|---|---|---|---|
| `provider` | `'auto' \| 'react-native' \| 'react' \| PlatformAdapter` | `'auto'` | Which platform renders. `'auto'` uses the provider the bundler included. An explicit name throws a clear error when it does not match the bundle. An adapter object plugs in [a custom platform](/reference/platform-adapter/). |
| `theme` | `Partial<EngineTheme>` | none | The theme. Shortcut for [`updateTheme(theme)`](/reference/theme/). |
| `breakpoints` | `Record<string, number>` | `{ sm: 480, md: 768, lg: 1024, xl: 1280 }` | Minimum widths (px) used by `when('breakpoints:…')`. Replaces the whole set. See [Responsive design](/guides/responsive/). |
| `native.remBase` | `number` | `16` | Pixel size of `1rem` (and the fallback for `em`) on React Native. |
| `modules` | `IsoModules` | all off | The optional modules to turn on. |
| `performance.inline` | `boolean` | `true` | With the [JSX runtime](/guides/performance/#rendering-without-the-wrapper), render styled components whose style never reads the theme without their wrapper. Set it once, at startup. |
| `performance.themeVariables` | `string[]` | off | Web only. Theme keys whose values are CSS strings, exposed as CSS variables so a theme switch does not re-render. See [Theme as CSS variables](#theme-as-css-variables). |

Not calling `configure()` at all behaves like `configure({ provider: 'auto' })`.

### How the platform is chosen

`configure({ provider })` selects and validates the provider; the **bundler** decides which code ships:

- Metro on iOS and Android loads the React Native adapter (`providers/index.native`).
- Vite, webpack, Next and Metro web load the React DOM adapter (`providers/index`).

So a web bundle never contains `react-native`, and a mobile bundle never contains the DOM adapter.

| `provider` | Behavior |
|---|---|
| `'auto'` (default) | Use whatever the bundler included. |
| `'react-native'` / `'react'` | Explicit. Throws a clear error if it does not match the bundle. |
| adapter object | Plug in another platform (see [`PlatformAdapter`](/reference/platform-adapter/)). |

Components are defined *before* `configure()` runs (imports are hoisted), so `engine('Box')` only stores the primitive's **name**; the real component is resolved at render time by the active provider. Call `configure()` once, at boot: switching providers after the first render only produces a development warning.

### Theme as CSS variables

By default a theme switch re-renders every styled component that reads the theme. On the web, list the theme keys that hold CSS-ready strings and the switch becomes one `:root` rewrite:

```ts title="web entry"
configure({ performance: { themeVariables: ['color'] } });
```

Styles that read `theme.color.background` then compile to `background-color: var(--iso-color-background)`, and the real values live in a single `:root{--iso-color-background:…}` rule that follows `updateTheme`. A component that only reads those tokens does not subscribe to the theme, does not re-render and does not recompile. With 1,000 components mounted, a light↔dark switch went from 1,000 renders to none in the benchmark (`yarn bench`).

<Aside type="caution" title="What the style may do with those values">
The listed branches must hold CSS strings that the style only **passes through**: `backgroundColor: theme.color.bg`, or inside a template string (`` `0 0 4px ${theme.color.shadow}` ``). Computing with them (`theme.color.bg + '80'`, parsing a color, comparing a string token such as `theme.mode === 'dark'`) sees the text `var(--iso-…)`, not the value. List only keys that are plain CSS values.
</Aside>

- Numbers, booleans and every key you did not list stay real values. A style that reads one of them keeps following the theme, exactly as without the option.
- Define the tokens up front, in `configure({ theme })`: a token added later is not seen by styles that were already compiled.
- It is part of the server-rendered CSS (`getStyleText()` starts with the `:root` rule).
- On React Native the option is ignored, with a development warning: tokens stay values there. Set it in the web entry only.

## `isoform.config.json` and optional modules

The media players, the PDF viewer, the bottom sheet, SVG, the camera, the date picker, the image pipeline and the modal are **optional and off by default**, so apps that do not use them pay nothing: no native code, no dependencies, no bundle size. Turn them on in one file at the app root, next to `package.json`, and pass the same file to `configure`:

```json title="isoform.config.json"
{
  "modules": {
    "video": { "enabled": true },
    "audio": { "enabled": true, "mediaSession": false },
    "pdf": { "enabled": true },
    "sheet": { "enabled": true },
    "svg": { "enabled": true },
    "datePicker": { "enabled": true },
    "image": { "enabled": true },
    "modal": { "enabled": true },
    "camera": { "enabled": true, "video": true, "codeScanner": true }
  }
}
```

```ts
import { configure } from '@michelgutner/isoform';
import isoform from './isoform.config.json';

configure({ modules: isoform.modules });
```

Each module takes `true` or an object (`{ "enabled": true, ...options }`), so `"video": true` works too. A module is only on with `true` or `enabled: true`; an object without it stays off.

### Module options

| Module | Option | Default | What it does |
|---|---|---|---|
| `audio` | `mediaSession` | `false` | Background audio with lock screen and notification controls. **Build-time only.** See [Audio](/modules/audio/#background-audio-and-system-controls-mediasession). |
| `pdf` | `workerSrc` | none | Web only: URL of the pdf.js worker, to parse PDFs off the main thread. See [PDF](/modules/pdf/#web-worker). |
| `camera` | `video` | `false` | Video recording (`startRecording`), adds the microphone permission. |
| `camera` | `codeScanner` | `false` | Barcode and QR scanning (`onCodeScanned`). |

### What the file decides in each build

The same file drives every build, so a disabled module is really left out:

| Where | What the file decides |
|---|---|
| Web (Vite, webpack, Next) | Each module is a separate chunk, downloaded only when the module is on and one of its components renders. |
| Metro (iOS/Android JS) | `withIsoform` in `metro.config.js` swaps disabled modules for an empty stub. |
| Android (Gradle) | Media3, Compose and the module's Kotlin code are only compiled when on. |
| iOS (CocoaPods) | The module's Swift and Objective-C++ are only compiled when on, with an empty shell otherwise. |

```js title="metro.config.js"
const { withIsoform } = require('@michelgutner/isoform/metro');

module.exports = withIsoform(getDefaultConfig(__dirname));
```

<Aside type="caution" title="iOS reads the file at pod install">
If you change `isoform.config.json`, run `cd ios && pod install`: the build stops with a clear message if the two are out of sync. Without the file, every module is compiled and only `configure()` decides at runtime.
</Aside>

### When a module is off

Rendering a component of a disabled module never crashes. It logs one development warning that names the module and the `configure({ modules: { … } })` call that turns it on, and renders a fallback. Each module page lists its fallback; in short:

| Module | Web, module off | iOS/Android, module off |
|---|---|---|
| `video` | an empty box with the same style | an empty black box with the same style |
| `audio`, `pdf` | an empty box with the same style | an empty box with the same style |
| `camera` | an empty box with the same style | nothing |
| `sheet`, `svg`, `datePicker` | nothing | nothing |
| `image` | a plain `<img>` | React Native's `Image` |
| `modal` | nothing | React Native's `Modal` |

See the [modules overview](/modules/overview/) for what each module draws on each platform.
