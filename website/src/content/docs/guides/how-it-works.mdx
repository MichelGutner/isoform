## Architecture

```
src/
  index.ts              single public entry (imports ./providers/index)
  config/               configure(), provider registry
  providers/
    index.ts            web:    registers the React DOM adapter   (Vite / webpack / Next / Metro web)
    index.native.ts     mobile: registers the React Native adapter (Metro iOS/Android)
  core/                 platform-agnostic: builder, engine, conditions, types (never imports react-native/react-dom)
  theme/ cache/ hash/   platform-agnostic
  adapters/
    react-native/       primitives → RN components, CSS → RN style normalization
    react-dom/          primitives → DOM, props translation, atomic CSS sheet
```

A test (`src/boundaries.test.ts`) fails the build if the core imports `react-native`/`react-dom`, or if one provider reaches the other platform's adapter.

## Render pipeline

1. Read the current theme and the active adapter (`getProvider()`); `platform = adapter.os()`.
2. Run the rules (`style`, `when`, `attrs`) into one merged style object and merged props. While they run, the props and the theme they see report what was read. The result is cached by the props the rules actually read (a `testID` or an `onPress` that changes does not count), and per theme only once a rule read the theme. Components whose rules do not depend on props skip hashing entirely.
3. `adapter.compileStyle(style, states, breakpoints, pseudos)` (cached with the step above): React Native normalizes CSS values; the DOM adapter emits atomic classes.
4. `adapter.applyProps(...)` (every render, cheap): translates universal props and merges the user's `style`/`className`.
5. Subscribe to the theme store, with a snapshot that only changes on a theme switch if the style read the theme.

With the [JSX runtime](/guides/performance/#rendering-without-the-wrapper), steps 1 to 4 run while the parent creates the element, for styled components whose style never reads the theme: the element is the component underneath, and step 5 is not needed.

## Atomic CSS on the web

Each `property: value` declaration becomes one class (`o-<hash>`), deduplicated across the whole app. All classes have the same specificity, so rules are inserted by **rank** to keep CSS semantics intuitive:

| Rank | Contains |
|---|---|
| 0 | primitive base rules |
| 1 | total shorthands (`padding`, `margin`, `border`, `background`, `font`, `flex`…) |
| 2 | group shorthands (`borderWidth`, `borderColor`, `borderRadius`…) |
| 3 | side shorthands (`borderTop`…) |
| 4 | longhands (`paddingLeft`, `color`…) |

So `{ padding: 4, paddingLeft: 8 }` yields `padding-left: 8px` regardless of key order, and a primitive's base style never overrides yours. State rules (`:hover` → `:focus` → `:focus-visible` → `:active`), pseudo-elements and breakpoint rules (ordered by width) live in later blocks.

Highly dynamic values (a `width` that changes with every prop value) create one class per distinct value, the usual atomic-CSS trade-off. For fully dynamic values, use the inline `style` prop.

## The React Native adapter

- Normalizes the CSS vocabulary into React Native styles (see [Style vocabulary](/guides/style-vocabulary/#how-mobile-converts-values)).
- `type="password"` on `Input` becomes `secureTextEntry`. Everything else is passed straight to the React Native component.
- Deprecated React Native exports (such as `SafeAreaView`) are read lazily, so you only get React Native's deprecation warning if you use them.
- A single **style host** tracks what a style depends on at render time (window width for breakpoints, `pressed`, `focus`). Hosts are only created for components that need them, cached per component, and chained as `styleHost` → `transitionHost` → `animatedHost` → component.

## The React DOM adapter

- Translates props: `onPress`, `onChangeText`, `onSubmitEditing`, `testID`, `disabled`, `multiline`, `numberOfLines`, `placeholderTextColor`, `secureTextEntry`, `editable`, `keyboardType`, `source`, `accessibilityLabel/Role/Hint/State`.
- Filters props per element: only attributes valid for the target element, `data-*`, `aria-*` and `on*` handlers reach the DOM. Style-driving props never leak.
- Removes mobile-only props (`hitSlop`, `onLayout`, `activeOpacity`…).
- Applies the user's `style` prop inline (it always wins) and concatenates `className`.

## Custom providers

A provider implements [`PlatformAdapter`](/reference/platform-adapter/) and is passed with `configure({ provider: myAdapter })`.
