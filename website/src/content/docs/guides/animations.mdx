## Keyframes

[`keyframes()`](/reference/keyframes/) declares an animation once and returns its name; use it in the CSS `animation` properties.

```tsx
import { engine, keyframes } from 'react-isoform';

const pulse = keyframes({
  from: { opacity: 1, transform: 'scale(1)' },
  '50%': { opacity: 0.5 },
  to: { opacity: 0.35, transform: 'scale(0.8)' },
});

const Dot = engine('Box', {
  width: 14,
  height: 14,
  borderRadius: 7,
  backgroundColor: 'seagreen',
  animation: `${pulse} 900ms ease-in-out infinite alternate`,
});
```

- **Web**: real `@keyframes` + `animation` in the atomic stylesheet (GPU-friendly, works with SSR). Unused keyframes emit no CSS.
- **Mobile**: the same declaration runs on React Native's `Animated`. `opacity` and `transform` use the native driver; layout properties (`width`, `height`, colors…) fall back to the JS driver.

`keyframes()` does not depend on the active provider: it only stores the definition and returns a content-hashed name (`o-kf-<hash>`), so it can be called at the top of a module, before `configure()`.

**Supported on both platforms**: the `animation` shorthand and the longhands (`animationName`, `animationDuration`, `animationDelay`, `animationTimingFunction`, `animationIterationCount`, `animationDirection`, `animationFillMode`, `animationPlayState`); `from`/`to`/`N%` frames (also `'0%, 100%'`); easings `linear`, `ease*`, `cubic-bezier()`, `steps()`; `reverse`/`alternate` directions. You can also inline the frames: `animationName: { from: {…}, to: {…} }`.

**Mobile limits**: only the **first** animation of a list runs; fractional iteration counts are rounded; properties that cannot be interpolated (`alignSelf`…) are skipped with a development warning. Missing 0% and 100% frames fall back to the base style (identity for transforms), as in CSS.

## Transitions

CSS `transition` animates style **changes**: from props, from states (`pressed`, `focus`) or from breakpoints.

```tsx
const Card = engine<'Box', { open?: boolean }>('Box', {
  width: 120,
  backgroundColor: '#6366f1',
  transition: 'background-color 500ms ease, width 500ms cubic-bezier(0.2, 0.8, 0.2, 1), opacity 300ms',
}).when('props:open', { style: { width: 260, backgroundColor: '#16a34a' } });

const Press = engine('Pressable', { transition: 'transform 160ms ease-out' })
  .when('state:pressed', { style: { transform: 'scale(0.94)' } });
```

- **Web**: plain CSS `transition`, declared in the atomic sheet.
- **Mobile**: a host animates the final style with `Animated` whenever a transitioned property changes (the first render does not animate). Supported: the `transition` shorthand and the longhands (`transitionProperty`, `transitionDuration`, `transitionTimingFunction`, `transitionDelay`), `all`, per-property timing and delay, `ease*`/`cubic-bezier()`/`steps()`, numbers, colors, strings with matching numbers (`'10%'`, `'45deg'`) and `transform` (function by function). `opacity`/`transform` use the native driver; anything else (or `all`) uses the JS driver.
- An interrupted transition continues from where it was (numbers, colors, matching strings); otherwise it restarts from the previous value.
- A value that cannot be interpolated (for example `width: 'auto'` → `100`) changes instantly, with a development warning.

<Aside type="caution">
- With `animation` and `transition` on the same element, mobile runs only the `animation` (with a development warning).
- Whether an element has `transition`, `animation` or breakpoints must not depend on its props: mobile picks the hosts that animate a component once.
</Aside>
